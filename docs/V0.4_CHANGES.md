# v0.4.0 build 9

## 用户反馈与已复现原因

用户要求白天可用的浅色设计，并反馈 DeepSeek HTTP 400。截图里的模型 ID 是 `DeepSeek-Flash`，官方服务当前返回的准确 ID 是 `deepseek-flash`，另有 `deepseek-v4-pro`。通过仅访问官方 API 的诊断，模型列表请求 HTTP 200，使用截图模型 ID 的翻译请求返回 HTTP 400、invalid_request_error、模型相关错误。显示名 `DeepSeek-V4.1-Flash` 不等于 API ID。

正确 ID 的诊断请求仍出现服务响应延迟：非流式请求超过 25 秒；流式请求保持连接但数分钟没有译文，诊断已终止。随后 `deepseek-v4-pro` 试译成功：非流式样本约 5.67 秒；与 App 同协议的流式样本首字约 2.25 秒，完整译文约 2.40 秒，返回 HTTP 200 与完整结束标记，译文为 “Hello, what time shall we meet tomorrow?”。Flash 在 /v1 流式请求也未于 25 秒内返回文字。因此默认模型改为已在此次诊断通过的 Pro，可获取列表并自行测试其他模型。不能把模型列表请求通过等同于翻译成功，也不能用一条短句承诺所有对话的延迟。未将用户密钥写入项目、文档或 IPA。

## 实现

- 默认浅色：奶白背景、蓝色主按钮、柔和蓝色/米色双语气泡、紧凑麦克风控制区。保留可选深色模式。
- 地址与密钥填写后可获取服务器的模型列表，搜索、点选准确模型 ID。支持 OpenAI 兼容、中转、Anthropic 和 Gemini 原生列表与分页；部分服务不提供列表时允许手动输入。
- 测试成功收到完整译文后才能保存并启用新配置。获取列表与失败测试不覆盖已有配置。测试显示等待秒数。
- 更新 DeepSeek 默认模型为此次实际试译成功的 `deepseek-v4-pro`；官方主机关闭思考模式，避免为文字翻译等待无用推理。第三方服务不会收到此专有参数。
- 错误按模型、密钥/权限、余额、限流和网络分类，保留 HTTP 状态，不展示可能含密钥或原文的上游原始错误。
- 翻译设置总等待期限，避免服务器只发保活信息时一直旋转。保留完整性验证，不将截断译文当测试成功。

## 范围

最低 iOS 15；连续双语语音识别、本地录音与文字导出保持。此次没有加入账户、拍照翻译、广告或云同步。第三方服务能否访问与翻译仍取决于其协议、模型权限、余额和网络。
