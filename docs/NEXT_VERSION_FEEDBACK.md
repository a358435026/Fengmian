## 优先问题：有原文但没有译文

用户实测：新版无法翻译，填写 DeepSeek 密钥后仍无反应。截图中英语与中文条目均显示“识别待确认”，没有译文。

代码已确认：ConversationModel.receive 将 needsConfirmation 为 true 的条目排除在翻译队列之外。这些条目不会请求 API。现有识别确认规则会阻塞正常连续对话，需要优先调整；不能根据截图直接认定密钥无效，也不能据此认定密钥或网络连接正常。

下一阶段需分别验证识别分段、语言判断、翻译入队、密钥读取、真实 API 请求与结果显示，并让失败原因可见。保留低可靠性提示与原文修正能力，但不能让正常对话普遍停留在手动确认。具体策略待下一阶段设计和验证，不通过猜测补造原文。

## API 设置与测试

用户要求支持主流大模型官方 API，同时支持第三方中转站 API。

当前不足：界面只有密钥输入与保存，DeepSeek 地址和模型写死，无连接或翻译测试。

下一版配置需包含服务商、API 地址（明确 Base URL 与完整端点的区别）、模型名称、密钥，以及可验证的测试功能。测试应显示成功或失败、实际译文、耗时和可理解的错误原因；保存成功不能冒充连接成功。需支持自定义地址与模型，并按服务商实际协议实现适配，不能假设所有官方 API 都兼容 OpenAI 格式。密钥继续安全存储，日志与错误信息不得泄露密钥。

## 手机 UI

用户明确反馈：当前页面过于简陋、外观不好，需要重新优化。

等待用户提供示意图后再确定布局、视觉风格、颜色、字体和交互。简洁实用仍为核心，原文与对应译文清晰成组，录音与翻译状态明确，设置完整且易用；不增加无关功能。

## 保持的核心要求

- 原生 iPhone 程序，最低支持 iOS 15，交付可供 TrollStore 安装测试的 IPA。
- 一次开始后持续收音，双方自然轮流说话，自动生成每段原文及另一种语言的译文，不要求每句话重新点击语言按钮。
- 准确性优先，分别评估语音识别与文字翻译；速度指标必须说明计时范围并实测，不承诺未经验证的零点几秒全链路延迟。
- 录音结束后可选择保存或丢弃；保存到本地，并保留本地导出能力。
- 翻译提示词可参考用户提供的沉浸式翻译模板，但提示词无法替代正确的语音识别。
